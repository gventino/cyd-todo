# Findings for cydui

Everything in the library that got in the way while writing this application, one entry each, with what happened, what was done in the application, and what the library should do (fix, document, or leave). Closing this file out is the condition for `cydui` 1.0.0.

| # | Where | What happened | Application workaround | Library action | State |
|---|---|---|---|---|---|
| 1 | `cydui_draw_bitmap` and dirty regions | The hash of a strip compares the bitmap **pointer** (and its size), not its pixels, so a QR of the same size drawn into the same buffer with new content is **not redrawn**. Reproduced in `test_qr.c` (a code of another size is redrawn by itself, which hides the bug until two links happen to have the same length). | `todo_qr_set()` calls `cydui_invalidate()` when the code changed; tested against a fresh screen (A3.4). | Document it in `docs/12-guide.md` (already in the header of `dirty_mem`; add the QR case). | documented in rc.2 (guide section 9, `cydui_draw_bitmap`) |
| 2 | `cydui_theme` (A3.3, 2026-11-25) | A theme has **one** font (`style.font`): the widgets measure with it, but the app needs a 24 px bold heading, a bold 16 px label and a 12 px caption besides the 16 px body. | The theme's font is the 16 px serif; our own widgets pass the font to `cydui_draw_text` themselves (`todo_serif_*`). | Document that painters and custom widgets may use any font; consider a `font_small`/`font_title` pair in `cydui_style`. | **fixed in rc.2** (`font_small`, `font_title`, `cydui_theme_font`) |
| 3 | text helpers (A3.3) | There is no "fit this text in N pixels with an ellipsis": long titles had to be cut by hand. Also, the width of a whole string is **not** the sum of the widths of its pieces (the font rounds the advance), so a cut found by adding up measured too little by up to 4 px. | `todo_fit_ellipsis()` in `theme_quest`: estimate by pieces, then measure the real string and back off a character at a time, on UTF-8 boundaries. | Offer `cydui_text_fit(font, s, len, max_w)` returning the byte length that fits (with an optional ellipsis), measured as drawn. | **fixed in rc.2** (`cydui_text_fit`, `cydui_text_ellipsize`); adopted |
| 4 | theme tables (A3.3) | The table (`fill/border/text/accent`, one border width, one radius) cannot say "a card with a gold bar on one side", "a tab whose active state is the page itself" or an edge made of two colors; everything that is more than a flat slab needs a painter. | Painters of stacked rectangles (`paint_button`, `paint_tab`, `paint_page`, ...) that still call `cydui_paint_default()` for the content; 3 to 6 commands each. | Nothing to change: this is what painters are for. Worth a paragraph in the guide with the two-rectangle "boxed" idiom. | documented in rc.2 (guide section 9) |
| 5 | `cydui_theme` painters (A3.3) | A painter gets the `cydui_theme*` but nothing says which palette the app built it with, so a painter that needs colors outside the table (the gold highlight, the wood edge) has to find them again. | The painter looks the palette up from the theme **name** (`quest-parchment` / `quest-candlelight`). Works, but is a string compare per widget. | Add a `void *user` to `cydui_theme` for the application's own data. | **fixed in rc.2** (`cydui_theme.user`); adopted |
| 6 | bitmap formats (A3.4) | Only 4 bits per pixel exist (`CYDUI_BITMAP_A4`), so a QR code, which is 1 bit per module, costs 4 px x 4 px x 4 bits per module: **13.4 KB** for a version 4 code (16.2 KB at version 5) against about 0.2 KB for the matrix itself. It is the largest single buffer of the UI. | The mask is rendered once into a buffer the UI owns and reused for every code (link, Wi-Fi, address). | A 1 bpp format with an integer scale (`CYDUI_BITMAP_A1`, scale 4) would draw the matrix directly and need no buffer. | **fixed in rc.2** (`CYDUI_BITMAP_A1`); adopted: -16 KB |
| 7 | root layout (A3.5) | The margin of the root layout is `style.spacing`, the same number as the gap between widgets: an edge-to-edge screen (tabs flush with the top, a status line flush with the bottom) needs `spacing = 0` for the whole theme, and every container that wants a gap must ask for one. It was found as an 8 px offset of everything in the first picture. | `spacing = 0` in the `quest` theme, with a comment; `cydui_set_spacing()` where a gap is wanted. | Separate `style.margin` from `style.spacing`, or document it in the guide. | documented in rc.2 (guide, `cydui_set_spacing`) |
| 8 | touch targets vs a month (A3.5) | `style.min_target` is 32 px, but a month of six rows in the 192 px under the tabs leaves 22 px per row (26 px with five rows, which is most months); the cells are 45 px wide. | One target over the whole grid (`cydui_interact`) and the cell worked out from `resp.x/y`, pure and tested over every pixel (`cal_cell_at`); the 22/26 px height is judged in the pictures and at the board (A4). | Nothing to change in the library; worth a sentence in the guide on targets that are wide but short. | documented in rc.2 (guide section 9) |
| 9 | `cydui_label_wrapped` (A3.5) | The wrapped label draws in the theme's one font and color, so a bold wrapped title needs its own widget (measure with `cydui_text_size(.., wrap_w)`, allocate, draw with `wrap_w`). | `ui_wrapped()` in `components/ui/src/widgets.c`, 12 lines. | Take an optional font and color (`cydui_label_wrapped_ex`), or a `cydui_next_font()` modifier; see also finding 2. | **fixed in rc.2** (`cydui_next_font/color`, wrapped label); adopted |
| 10 | usage of the UI memory (A3.5) | `cydui_cmd_count` says how many commands a frame used, but nothing says how much of the text memory or how many state entries were used, and a full state table raises no flag (a scroll offset is just lost). The budget guard found the text need by shrinking the buffer until the worst-case scenes failed: between 512 and 768 bytes (the board gets 1536); the state need could not be found that way (16 entries still passed every scene). | The guard keeps the board's sizes (320 commands, 1536 text bytes, 64 states) and the busiest frame is 112 commands; 64 states stays a safe guess until A4 measures it on the board. | Expose high-water marks (`cydui_ui_stats`: commands, text bytes, state entries, tweens) and a flag for a full state table. | **fixed in rc.2** (`cydui_ui_stats`, `CYDUI_ERR_STATE_FULL`); adopted: 15 of 64 states measured |

| 11 | touch events (A6.2) | The application needed to know when the screen was last touched (the backlight timeout) and the library has no hook for it. | `poll_event` of the backend is wrapped by the application, which notes every DOWN and passes the event on untouched (`main/app_main.c`). It works, and the touch that wakes the screen is still a normal tap. | Document the wrapper as the recommended idiom for idle, screensaver and backlight policies; no API change. | documented in rc.2 (guide section 9) |
| 12 | `cydui_animate` (A6.3) | A tween moves only when its target *changes*, which is what keeps lists from animating on load, but "animate once, when an event happens" (a toast fading, a level-up pulse) has no target that changes: the application salts the id with a counter of its own (`toast_seq`, `pulse_seq`) so each occurrence is a new tween that starts at `from`. | The counters in `todo_app`, 0 meaning "never", so nothing starts at boot. | Document the salted-id pattern in the guide, or offer `cydui_animate_once(ui, id, from, to, ms, ease)` that restarts when a caller-given generation number changes. | documented in rc.2 (guide section 9: the salted id) |
| 13 | text drawing (A6.3) | `cydui_draw_text` takes an alpha, but the usual helper path (`ui_text` in this application, and the labels of the library) draws at 255, so fading a toast meant calling the low-level function and centring the text by hand. | A direct `cydui_draw_text` with the centre worked out from `cydui_text_size`. | Let `cydui_label` and friends take the alpha of a `cydui_next_alpha()` modifier, or document the direct call. | **fixed in rc.2** (`cydui_next_alpha`) |
| 14 | `cydui_ui_end` (A6.3) | Its return value ("something is still moving") is what lets the loop sleep 250 ms when nothing happens and keep drawing exactly as long as an animation lasts; this was found by reading, not documented. | The loop relies on it (`main/app_main.c`). | Say so in the guide's section on the main loop. | documented in rc.2 (guide section 9) |
| 15 | labels and glyph tops (rc.2 migration) | The library's labels clip to their box (`e.w` by `lines * line_height`), which is right, but the application's serif fonts (generated with an `ascent` of 11 and 15) have glyph tops one pixel above it (tall ascenders, a few capitals): moving the wrapped texts from the application's own widget (which did not clip) to `cydui_label_wrapped` cut that row, 2 to 12 pixels on the 27 scenes and runs that have a wrapped text. | Accepted: the goldens were re-rendered and looked at. | A font generator that sets `ascent` to the real top of the tallest glyph (and `line_height` with it), or, in the library, a clip a pixel or two bigger than the box; for the application: regenerate the fonts with more room, which moves every line and every golden, so it waits. | open (small) |

*(Entries are added as they are found, with the date and the step.)*

## Summary at the end of A3 (the UI on the PC)
Ten entries, sorted by what is proposed for `cydui` **1.0.0**. The choice of what really goes into the library is the owner's; the findings of A5 and A6 (#11 to #14) are in the table above and in the summary below.

| Proposal | Entries |
|---|---|
| **Fix in the library** (small, and each one cost real work here) | #10 high-water marks for commands, text bytes, state entries and tweens, and a flag for a full state table; #5 a `user` pointer in `cydui_theme` so a painter finds the application's palette; #3 `cydui_text_fit` (the bytes that fit a width, with an optional ellipsis, measured as drawn) |
| **Document only** | #1 a QR (or any bitmap) redrawn in the same buffer needs `cydui_invalidate` (and the size is part of the hash); #4 the two-rectangle painter idiom; #7 the root margin is `style.spacing`; #8 wide-but-short targets |
| **Later / nice to have** | #2 more than one font per style; #9 a wrapped label in another font and color; #6 a 1 bpp bitmap with an integer scale (would remove 13 to 16 KB of the QR mask) |

Things that worked without friction are not entries: the scroll list with custom cards, popups, tweens for the XP bar, the id stack, `cydui_interact` for a month grid, the board-size memory (112 of 320 commands in the worst case).

## Update at the end of A6
Four more entries, all small. **Document only:** #11 wrap `poll_event` to observe touches (idle policies), #14 the meaning of `cydui_ui_end`'s return value for the main loop. **Fix or helper in the library, if cheap:** #12 an "animate once per occurrence" helper (or the salted-id pattern in the guide), #13 alpha for the label helpers. The decision of the owner at the end of A3 stands for the batch: **fix #10, #5, #3, #2, #9, #6; document #1, #4, #7, #8**, to which this update adds the two documents #11 and #14 and the two small items #12 and #13 for the owner to confirm when the batch is planned.

## After the rc.2 migration
Every entry of the batch was adopted by the application and its pictures were compared: the QR codes are pixel for pixel what the 4-bit mask gave (and the 37 scenes equal the PC's on the board, and the library's 42 gallery hashes too), and one new, small finding came out of the pictures (#15). Measured gains: **16 KB of heap** (`todo_app` 51 512 -> 35 504 bytes), 40 lines and their tests less in the theme, and the memory need of the busiest screen now known (112 commands, 524 text bytes, 15 state entries).
