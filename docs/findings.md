# Findings for cydui

Everything in the library that got in the way while writing this application, one entry each, with what happened, what was done in the application, and what the library should do (fix, document, or leave). Closing this file out is the condition for `cydui` 1.0.0.

| # | Where | What happened | Application workaround | Library action | State |
|---|---|---|---|---|---|
| 1 | `cydui_draw_bitmap` and dirty regions | The hash of a strip compares the bitmap **pointer**, not its pixels, so a QR drawn into the same buffer with new content is not redrawn. | A new buffer per QR, or `cydui_invalidate`. | Document it in `docs/12-guide.md` (already in the header of `dirty_mem`; add the QR case). | open |
| 2 | `cydui_theme` (A3.3, 2026-11-25) | A theme has **one** font (`style.font`): the widgets measure with it, but the app needs a 24 px bold heading, a bold 16 px label and a 12 px caption besides the 16 px body. | The theme's font is the 16 px serif; our own widgets pass the font to `cydui_draw_text` themselves (`todo_serif_*`). | Document that painters and custom widgets may use any font; consider a `font_small`/`font_title` pair in `cydui_style`. | open |
| 3 | text helpers (A3.3) | There is no "fit this text in N pixels with an ellipsis": long titles had to be cut by hand. Also, the width of a whole string is **not** the sum of the widths of its pieces (the font rounds the advance), so a cut found by adding up measured too little by up to 4 px. | `todo_fit_ellipsis()` in `theme_quest`: estimate by pieces, then measure the real string and back off a character at a time, on UTF-8 boundaries. | Offer `cydui_text_fit(font, s, len, max_w)` returning the byte length that fits (with an optional ellipsis), measured as drawn. | open |
| 4 | theme tables (A3.3) | The table (`fill/border/text/accent`, one border width, one radius) cannot say "a card with a gold bar on one side", "a tab whose active state is the page itself" or an edge made of two colors; everything that is more than a flat slab needs a painter. | Painters of stacked rectangles (`paint_button`, `paint_tab`, `paint_page`, ...) that still call `cydui_paint_default()` for the content; 3 to 6 commands each. | Nothing to change: this is what painters are for. Worth a paragraph in the guide with the two-rectangle "boxed" idiom. | noted |
| 5 | `cydui_theme` painters (A3.3) | A painter gets the `cydui_theme*` but nothing says which palette the app built it with, so a painter that needs colors outside the table (the gold highlight, the wood edge) has to find them again. | The painter looks the palette up from the theme **name** (`quest-parchment` / `quest-candlelight`). Works, but is a string compare per widget. | Add a `void *user` to `cydui_theme` for the application's own data. | open |

*(Entries are added as they are found, with the date and the step.)*
